# 工作流和技能的大纲设计

## 1) 阶段链路

Intent（what/why） → Design（how） → Build（实现） → Verify（一致性） → Distill（长期沉淀） → Archive

### 关键原则

- what/why 与 how 分层存放。
- 实现后先 Verify，再 Distill。
- 不允许跳过 Distill 直接 Archive。

## 2) Skills 设计（可直接落地）

| Skill | 主要职责 | 输入 | 输出 | 退出条件 |
|---|---|---|---|---|
| intent-clarify | 收敛 what/why、边界、非目标 | 口述需求/问题 | intent.md | 目标、边界、验收口径清晰 |
| contract-spec | 产出行为契约（what） | intent.md | spec.md（按 capability） | 每条需求可验证且有场景 |
| solution-design | 产出 how（架构/接口/数据/交互方案） | intent.md + spec.md | design/ | 关键决策、权衡、风险齐全 |
| task-plan | 把 how 拆成可执行任务 | design/ | tasks.md | 任务可独立完成并验收 |
| implement | 按 tasks 实施 | tasks.md | 代码 + 任务勾选 | 任务完成或阻塞明确 |
| verify | 校验 code ↔ spec/design 一致性 | 代码 + spec + design/ | verify.md | 差异清单清零或确认例外 |
| sync-contract | 回写长期 WHAT | spec.md 增量 | 主线 docs/specs/* | 主线行为文档与实现一致 |
| distill-how | 提炼长期 HOW（重点） | design/ + 实现结果 | docs/design/* + docs/architecture/* | 至少沉淀“可复用决策 + 模式” |
| archive-change | 冻结变更上下文 | 全部产物 | 归档目录 | Verify 通过且 Distill 完成 |

## 3) 目录结构（运行态与长期沉淀分区）

```text
project-root/
├── .workflow/                          # 运行态（流程过程、单次变更、版本执行）
│   ├── AGENTS.md                       # .workflow 治理规则
│   ├── intents.md                      # 全局 what/why、关键意图、意图变更
│   ├── roadmap.md                      # 全局路线图、进度、阻塞、下一步
│   ├── templates/                      # 运行态模板文件
│   ├── changes/                        # 单次变更工作区
│   │   └── <change-id>/                # 语义化变更标识，不是数字编号
│   │       ├── intent.md               # what/why（本次）
│   │       ├── specs/
│   │       │   └── <capability>/spec.md # 本次行为契约增量
│   │       ├── design/                 # 本次 how（架构/交互/技术决策）
│   │       ├── tasks.md                # 本次实施清单
│   │       ├── verify.md               # 本次一致性证据
│   │       └── artifacts/              # 截图、基准、测试证据等
│   └── archive/                        # 已完成变更的完整上下文
│       └── YYYY-MM-DD-<change-id>/     # 日期 + 语义化变更标识
│
└── docs/                               # 长期沉淀（主线知识）
    ├── AGENTS.md                       # docs 治理规则
    ├── index.md                        # docs 本层索引
    ├── templates/                      # 长期文档模板文件
    ├── specs/                          # 长期 WHAT
    │   ├── index.md
    │   └── <capability>/spec.md
    ├── design/                         # 长期 design 内容（从运行态 design 提炼）
    │   └── index.md
    ├── architecture/                   # 长期 HOW（系统级）
    │   ├── index.md
    │   ├── system-overview.md
    │   ├── module-boundaries.md
    │   ├── integration-patterns.md
    │   ├── ui-architecture.md
    │   └── adr/                        # 架构决策记录（长期，ADR）
    │       └── ADR-YYYYMMDD-*.md
    └── runbooks/                       # 运维/故障/迁移手册
        └── index.md
```

## 4) 运行态 vs 长期沉淀

| 类型 | 位置 | 生命周期 | 是否自动同步 |
|---|---|---|---|
| 运行态文档 | `.workflow/changes/<id>/...` | 变更期间活跃 | 否 |
| 长期 WHAT | `docs/specs/...` | 持续演进 | 由 sync-contract 更新 |
| 长期 HOW | `docs/architecture/...` | 持续演进 | 由 distill-how 更新（强制门禁） |
| 历史追溯 | `.workflow/archive/...` | 永久保留 | 由 archive-change 生成 |
