# 工作流和技能的大纲设计

## 1) 阶段链路

Intent（原始意图） → Roadmap（版本与变更编排） → Design（how） → Build（实现） → Verify（一致性） → Distill（长期沉淀） → Archive（版本归档）

### 关键原则

- `intents.md` 只保存尚未进入 roadmap 的原始意图。
- `roadmap.md` 是当前活跃 versions/changes 的索引，不是历史总账。
- Agent 不能只机械消费 intents；需要基于项目现状主动规划必要的铺垫、验证、质量和治理 changes。
- 实现后先 Verify，再 Distill。
- 归档以 version 为单位，归档后从活跃 roadmap 移入 archive。

## 2) Skills / Commands 设计（可直接落地）

| Skill / Command | 主要职责 | 输入 | 输出 | 退出条件 |
|---|---|---|---|---|
| setup-workflow | 初始化/更新 `.workflow/` 与 `docs/` 两个关键目录，并注入 `CLAUDE.md` / `AGENTS.md` 加载规则 | 项目现状 + 工作流模板 | `.workflow/` + `docs/` 基础结构 + 入口加载区块 | 两区结构、治理文件、模板、索引与入口加载规则可用 |
| help-workflow | 介绍整套工作流与可用技能 | 用户问题/当前阶段 | 工作流说明与推荐下一步 | 用户理解当前阶段和可用技能 |
| clarify-intent | 记录尚未进入 roadmap 的原始意图 | 口述需求/问题 | `.workflow/intents.md` | 意图进入“待讨论”或“未分配” |
| plan-roadmap | 编排活跃 versions/changes，并建立或更新 change 骨架 | `.workflow/intents.md` + `docs/` + `.workflow/roadmap.md` + `.workflow/changes/` + 按需 archive | `.workflow/roadmap.md` + `.workflow/changes/<change-id>/intents.md` | 活跃 roadmap 与 changes 目录一致 |
| specify-change | 产出单个 change 的行为契约（what） | `.workflow/roadmap.md` + `.workflow/changes/<change-id>/intents.md` | `.workflow/changes/<change-id>/specs/<capability>/spec.md` | 每条需求可验证且有场景 |
| design-change | 产出单个 change 的 how（架构/接口/数据/交互方案） | change intents + specs + 项目现状 | `.workflow/changes/<change-id>/design/` | 关键决策、权衡、风险齐全 |
| plan-task | 把 how 拆成可执行任务 | `.workflow/changes/<change-id>/design/` | `.workflow/changes/<change-id>/tasks.md` | 任务可独立完成并验收 |
| implement-task | 按 tasks 实施 | `.workflow/changes/<change-id>/tasks.md` | 代码 + 任务勾选 | 任务完成或阻塞明确 |
| verify-implementation | 校验 code ↔ spec/design 一致性 | 代码 + change specs + design | `.workflow/changes/<change-id>/verify.md` | 差异清单清零或确认例外 |
| sync-contract | 回写长期 WHAT | change specs 增量 | `docs/specs/*` | 主线行为文档与实现一致 |
| distill-how | 提炼长期 HOW | change design + 实现结果 + verify 证据 | `docs/design/*` + `docs/architecture/*` | 可复用设计、架构决策或模式已沉淀 |
| archive-version | 以 version 为单位冻结上下文并迁入 archive | 完成的 version + 全部关联 changes | `.workflow/archive/roadmap.md` + `.workflow/archive/changes/` | version 已归档且活跃 roadmap 已移除 |

## 3) 关键文件职责

| 文件 / 目录 | 职责 |
|---|---|
| `.workflow/intents.md` | 只保存尚未进入 roadmap 的原始意图，分为“待讨论”和“未分配”。 |
| `.workflow/roadmap.md` | 当前活跃 versions/changes 的索引，标记当前焦点、下一步和阻塞项。 |
| `.workflow/changes/<change-id>/intents.md` | 单个 change 的来源记录：可能来自用户意图，也可能来自 Agent 主动规划出的铺垫/验证/质量/治理工作。 |
| `.workflow/changes/<change-id>/specs/` | 本 change 的行为契约增量。 |
| `.workflow/changes/<change-id>/design/` | 本 change 的 how 设计材料。 |
| `.workflow/archive/roadmap.md` | 已归档 versions 的索引。 |
| `.workflow/archive/changes/` | 已归档 changes 的完整上下文。 |
| `docs/` | 长期沉淀区，保存主线规格、长期设计、架构、ADR、runbooks 等。 |

```text

│   ├── AGENTS.md                           # .workflow 治理规则
│   ├── intents.md                          # 尚未进入 roadmap 的原始意图池
│   ├── roadmap.md                          # 当前活跃 versions/changes 索引
│   ├── templates/                          # 运行态模板文件
│   │   ├── intents.md
│   │   ├── roadmap.md
│   │   └── changes/

│   ├── changes/                            # 当前未归档 changes
│   │   └── <change-id>/                    # 语义化变更标识，不是数字编号
│   │       ├── intents.md                  # 本 change 的来源意图或规划来源
│   │       ├── specs/
│   │       │   └── <capability>/spec.md    # 本 change 的行为契约增量
│   │       ├── design/                     # 本 change 的 how（架构/交互/技术决策）
│   │       ├── tasks.md                    # 本 change 的实施清单

│   │       └── artifacts/                  # 截图、基准、测试证据等
│   └── archive/                            # 已归档 version 与 change 上下文
│       ├── roadmap.md                      # 已归档 versions 索引
│       └── changes/

│
└── docs/                                   # 长期沉淀（主线知识）
    ├── AGENTS.md                           # docs 治理规则
    ├── index.md                            # docs 本层索引
    ├── templates/                          # 长期文档模板文件
    ├── specs/                              # 长期 WHAT
    │   ├── index.md
    │   └── <capability>/spec.md
    ├── design/                             # 长期 design 内容（从运行态 design 提炼）
    │   └── index.md
    ├── architecture/                       # 长期 HOW（系统级）
    │   ├── index.md
    │   ├── system-overview.md

    │   ├── integration-patterns.md

        └── index.md
```

## 5) Intent / Roadmap / Change 关系

```text
.workflow/intents.md
  └─ 只保存待讨论 / 未分配意图
       ↓ plan-roadmap
.workflow/roadmap.md
  └─ 活跃 versions/changes 索引
       ↓ 建立或更新骨架
.workflow/changes/<change-id>/intents.md
  └─ 本 change 的来源意图或规划来源
```

规则：

- intent 一旦被 `plan-roadmap` 编排进 roadmap，就从 `.workflow/intents.md` 移除。
- roadmap 中每个活跃 change 必须对应 `.workflow/changes/<change-id>/`。
- change 不一定直接来自 intent；也可以来自 Agent 主动规划的铺垫、验证、质量或治理工作。
- big picture 由 Agent 按需读取 `docs/`、`.workflow/roadmap.md`、`.workflow/changes/`、`.workflow/archive/` 得到，而不是靠 `intents.md` 保存全部历史。

## 6) Version / Change 关系

- version 是当前开发队列中的可收口开发批次。
- 一个 version 可以包含多个 changes。
- 归档以 version 为单位进行。
- change 是单一可验证变更单元。
- change-id 是语义化变更标识，不是数字编号。
- 非 intent 直接来源的 change 必须在 `changes/<change-id>/intents.md` 中写明规划来源。

## 7) 运行态 vs 长期沉淀

| 类型 | 位置 | 生命周期 | 更新方式 |
|---|---|---|---|
| 待处理意图 | `.workflow/intents.md` | 进入 roadmap 前 | 由 clarify-intent 写入，由 plan-roadmap 移出 |
| 活跃路线图 | `.workflow/roadmap.md` | version 开发期间 | 由 plan-roadmap 维护 |
| 活跃 change | `.workflow/changes/<change-id>/...` | change 未归档前 | 由后续 workflow 命令逐步补齐 |
| 长期 WHAT | `docs/specs/...` | 持续演进 | 由 sync-contract 更新 |
| 长期 HOW | `docs/design/...` + `docs/architecture/...` | 持续演进 | 由 distill-how 更新 |
| 历史追溯 | `.workflow/archive/roadmap.md` + `.workflow/archive/changes/...` | 永久保留 | 由 archive-version 生成 |
