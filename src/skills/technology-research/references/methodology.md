# 技术研究方法论

技术研究的目标是形成可追溯判断，而不是引用某个固定最佳实践。

## 判断顺序

1. 明确问题类型：选型、升级、替换、配置、部署、性能、安全或维护。
2. 明确项目约束：当前技术栈、运行环境、团队经验、部署平台、兼容性、安全要求。
3. 查询当前资料：官方文档、release notes、包元数据、安全公告、迁移指南。
4. 对比候选方案：成熟度、维护状态、生态兼容、学习成本、锁定风险、迁移成本。
5. 形成推荐：说明为什么选、为什么不选、还需要验证什么。

## 推荐输出结构

```markdown
## 技术问题

## 项目约束

## 检索来源

## 候选方案

## 推荐方案

## 不选方案

## 风险与验证点

## 后续落点
```

## 资料优先级

1. 官方文档。
2. 官方 release notes / changelog / migration guide。
3. 包管理器元数据与安全公告。
4. 官方 GitHub issues/discussions。
5. 可信生态文章或案例。

不要把模型记忆、旧博客或孤立问答作为唯一依据。

## 记录要求

必须记录：

- 检索时间。
- 使用的资料来源。
- 选定版本或版本范围。
- 与项目约束的匹配关系。
- 未验证假设。
