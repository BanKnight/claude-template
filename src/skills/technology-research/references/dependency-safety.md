# 依赖与供应链安全

新增、替换或升级依赖时，不要只看功能是否满足，还要判断供应链风险。

## 检查项

- 当前稳定版本。
- 目标版本发布时间。
- 最近是否异常高频发布。
- 是否存在维护者变更、包名混淆、仓库迁移或安全公告。
- 依赖树是否显著扩大。
- 是否可以使用项目已有依赖替代。
- 是否可以用平台能力或少量项目内代码避免新增依赖。

## npm 7 天规则

默认不选择发布不足 7 天的 npm 版本，除非用户明确确认。

如果仍选择不足 7 天的版本，需要记录：

- 用户确认。
- 为什么不能等待。
- 降低风险的措施。
- 回滚方案。

## 低价值依赖判断

如果依赖只节省少量代码，但引入额外供应链、体积、维护或安全风险，默认不推荐新增。

## 输出要点

- 目标依赖与版本。
- 版本发布时间。
- 维护状态。
- 安全风险。
- 是否满足 7 天规则。
- 是否有替代方案。
