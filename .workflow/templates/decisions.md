## 记录规则

- 保留用户原始意图，不替用户重新设计。
- 决策变更要记录变更原因。
- 运行态决策放在这里；可长期复用的结论应在版本收口后沉淀到 `docs/`。

## 示例

### 2026-05-08 - setup 技能负责初始化工作流基础结构

**原始意图：**
用户希望项目能一键建立 `.workflow/` 与 `docs/` 的基础结构，而不是每次由 Agent 临时发挥。

**决策内容：**
`setup` 只负责初始化或更新工作流基础结构，包括治理文件、模板副本、入口加载规则和 docs 索引。

**原因：**
把基础设施初始化和后续需求澄清、设计、执行流程分开，可以减少职责混乱。

**影响范围：**
影响 `.workflow/`、`docs/`、`AGENTS.md`、`CLAUDE.md` 以及 `.workflow/templates/`。

**后续动作：**
后续 workflow 技能应基于 setup 生成的结构继续工作。
